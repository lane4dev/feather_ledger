# 有限前瞻物化窗口与周期生命周期边界

Type: grilling
Label: wayfinder:grilling
Status: resolved
Triage: ready-for-human
Blocked by: 01

## Question

在取消「无限历史欠账展开」与「有限次数删除后末尾补期」后，极简有限前瞻物化器的精确窗口、历史截断边界、结束条件以及账户归档/删除联动规则应如何定死？

## Context

Chart 阶段已锁定：
- 采用极简有限前瞻（非极简单指针，保证月度列表中可提前看到近期未来待入账账单）。
- 取消过去 40+ 天欠账全量展开，取消 `count` 有限次数系列删一期后末尾顺延补期。

本票需要决定的具体规则：
1. **未来前瞻窗口大小**：不同频率（每日 / 每周 / 每月 / 每年）的规则，物化未来多少时间/多少期最合适？（例如统一「未来 90 天内、最多 3 期（或每日/每周最多 4~8 期，每年至少提前 1 期）」的简洁上限，还是固定未来 N 天/固定最多 N 期）。
2. **历史欠账截断边界**：当用户很久没打开 App（或刚开启某条规则但起点在过去）时，如何避免展开几十条过期欠账？（例如仅物化「自今天起倒推不超过 X 天，或最多保留最近 1~3 个过期期次」；以及已被物化出来但长期未处理的过去期次是否永久保留在待入账列表里）。
3. **有限次数（`count`）与结束日期（`endDate`）完结语义**：`skipped` 期次是否明确占用一次 `count`；当全部期次均已 `posted` 或 `skipped`、或已超过 `endDate` 且无待入账实例时，系列如何收尾。
4. **与账户归档 / 账户删除的联动**：复用既有简明规则时，归档账户下的周期规则是继续暂停、仅冻结未来生成，还是需要顺手裁掉多余状态。

## Comments

- 用户确认（Round 1）：Q1=`a`（未来 90 天最多 3 期，保底未来 1 期）；Q2=`a` + 补充要求「如果启动时有新发现的、已经过期的未物化期次，在 UI 层面提醒用户」；Q3=`是`；Q4=`a`（以当前代码为准：归档账户停掉周期规则、保留已到期账单转为一次性待办，恢复账户不再复活周期规则，同时修正 `CONTEXT.md` 矛盾）。
- 用户确认（Round 2 追问）：1=`b`（只提示本次新补齐了 N 笔已到期账单，不展开截断技术细节）；2=`a`（纯会话级可手动关闭的非阻塞 Banner，零新增表/持久化字段）。

## Answer

1. **有限未来前瞻窗口（Lookahead Window）**：
   - 物化未来窗口收敛为：**以今天为起点向后 90 天内，每条活跃 `repeating` 规则最多保留 `3` 期未来 `scheduled` 实例，且至少保底生成未来 `1` 期**（用于兜住每年规则，去掉 `_floorLookaheadYears = 3` 的 3 年长距离前瞻）。
   - `planned` 规则（仅 1 期 `'single'`）按自身 `scheduledDate` 物化，不受 90 天滚动多期窗口限制。
   - 彻底取消 `extraCount` 末尾顺延补期逻辑。
2. **历史欠账全量补齐与会话级 UI 提醒**：
   - 启动/物化时若发现早于今天的未物化过期期次，**从 `series.startDate` 起补齐所有缺失的历史期次实例**（取消「最近 30 天内、单条规则最多补生成最近 3 期」的截断且不设人工硬截断上限）；已在表里的历史行（`scheduled`/`posted`/`skipped`/`failed`）保持幂等不重复生成。
   - 开启 `autoPost` 的活跃规则补齐的历史实例由自动入账流自动生成已入账交易记录（仅受备份恢复 `manualOnly` 与当前币种约束）；关闭 `autoPost` 的规则则生成 `scheduled` 待入账交易记录。
   - 物化命令（`ProjectRecurringEventsCommand`）返回新补齐且**不会自动入账、需用户手动核对**的过期实例数量 `newlyMaterializedOverdueCount`（即 `autoPost == false` 或 `manualOnly == true`）。当 `newlyMaterializedOverdueCount > 0` 时，账本页顶部展示一条**纯会话级、可手动关闭的非阻塞 Banner**（提示「本次新补齐了 N 笔已到期账单，请核对处理」，点击关闭或全部处理后消失；不新增表或持久化字段，下次启动不再对同一批已入库实例重复弹窗）。

> **[2026-11-23 规格调整对齐]**：原 Round 1/2 确认的「30 天最多 3 期历史欠账截断」已取消并改为无硬上限全量补齐；`newlyMaterializedOverdueCount` 仅统计非自动入账待核对实例。
3. **有限规则与 `skipped` 完结语义**：
   - 每次「跳过（`skipped`）」**消耗 `countLimit` 的 1 次计数**，绝不向后顺延新增期次。
   - 当全部期次都进入终态（`posted` / `skipped`）或超过 `endDate` 后，**物理保留 `RecurringSeries` 记录与历史实例行**（维持外键与 `sourceScheduledBillId` 溯源），物化器自然跳过不再生成。
4. **账户归档与生命周期统一**：
   - 以现有 `account_lifecycle_command.dart` 行为为准并同步修正 `CONTEXT.md`：账户归档时，仅将**已到期未处理**（`scheduled`/`failed`）的账单保留为一次性 `planned` 待办，原周期规则与未到期未来实例一并删除；恢复已归档账户时**不会**自动复活旧周期规则。
   - 物化查询与入账流程依然保持 `archived == false` 过滤防线。
