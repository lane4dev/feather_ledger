# 账本页 · M3 Expressive 浅色、暗色与日程列表

Triage: ready-for-agent

## Problem Statement

晚上翻账时，日期能跟着当前分组停在左侧，这是用户定位一笔交易的依据。但右侧每笔交易的分类标签占去一行，单笔日期又重复展示小计，连续几天的记录很难一眼比较。待入账整行变暗，恰好让最需要确认的状态难以辨认。月份按钮分得太开，月收支两列对齐不一，列表末尾的金额还需要明确的 FAB 避让空间。

## Solution

沿用 Google Calendar 日程式的左右分栏和日期交接手势。左栏标记哪一天，右栏用一张分组卡收拢当天所有流水。浅色模式以偏白的灰绿页面衬托逐级加深的卡片，暗色模式使用逐级提亮的深灰绿表面。两种模式共用日期吸附、双行布局、触控热区和底部避让规则。用户可以沿同一条右边线比较金额，通过副标题旁的状态标记辨认待入账，向上看可见实时余额与所选月的收支。底部导航保留「账本 / 预算 / 更多」。点资产概览卡可查看所选月的统计，搜索位于账本右上角，设置从「更多」进入。

## User Stories

1. 作为夜间记账的人，我希望从底色区分日期卡、概览和导航，以便快速找到正在看的区域。
2. 作为使用系统配色的人，我希望账本响应设备的动态颜色，在没有动态色的设备上也有清晰的浅色与暗色层级。
3. 作为逐月对账的人，我希望在紧凑的月份组合内点按前后箭头或月份，以便就近切换或直接跳到目标月。
4. 作为查账的人，我希望在右上角搜索，并能在「更多」里的设置页找到备份与恢复。
5. 作为在公共场合打开账本的人，我希望点余额标签旁的眼睛就能隐藏概览金额，同时继续核对流水。收起概览后，余额也应保持隐藏。
6. 作为回顾上月开销的人，我希望看到实时全部余额和明确标出月份的收入、支出，以便分清两种时间口径。
7. 作为查看统计的人，我希望点概览卡的箭头就能看到当前所选月的报表，返回时继续看原先的流水。
8. 作为连续滚动账本的人，我希望日期停在工具栏下方，直到下一天将其顶走，反向滚动时也能追溯到上一组。
9. 作为核对今日账目的人，我希望通过圆形日期徽章找到今天，并能读清过去与未来日期的星期。
10. 作为看同日多笔交易的人，我希望在一张卡中依次看到分类图标、标题、账户和对齐的金额，从而迅速定位每笔交易。
11. 作为管理预约账单的人，我希望读清账单标题，并从账户旁的时钟和文字辨认待入账、进入对应详情处理。
12. 作为核对日收支的人，我希望多笔流水才出现有意义的小计，只有一笔时直接查看该笔金额即可。
13. 作为使用不同币种的人，我希望正负号紧贴币种符号、数字等宽，以便逐行比较金额和方向。
14. 作为核对月末流水的人，我希望滚到底时能读完整个末条金额，同时可以用加号新建交易。
15. 作为切换任务的人，我希望从底栏切换到账本、预算或更多，并能通过胶囊和图标形状辨认当前所在页。
16. 作为白天查账的人，我希望在浅色卡片上读清账户名、收支金额和待入账状态，并能一眼认出今天。

## Implementation Decisions

### 色板与金额

| 表面角色 | 浅色默认值 | 暗色默认值 | 用途 |
| --- | --- | --- | --- |
| `surface` | `#F7FAF7` | `#111413` | 页面与顶部工具栏底色 |
| `surfaceContainerLow` | `#EFF4EF` | `#191D1B` | 同日账单卡，16–18 dp 圆角 |
| `surfaceContainer` | `#E6EDE7` | `#1B201E` | 底部导航栏 |
| `surfaceContainerHigh` | `#DFE6E1` | `#222826` | 资产概览卡，24 dp 圆角 |

- 全应用共用浅色、暗色和动态基础色板，切换到账本、预算、更多及其子页面时使用同一套表面角色。本次布局调整限于账本页及其顶部、底部导航。按用户选择的模式取对应亮度的系统动态色板；跟随系统时随亮度切换。动态色缺失或读取失败时使用对应列的项目默认值。两种来源均需保持表面层级与前景对比。暗色模式避免纯黑页面和纯白控件。
- 页面和卡片的表面色、今日徽章、FAB 和导航指示器跟随动态色。收入与支出保留各自的语义色相，根据实际底色调整明暗；分类圆标沿用用户的分类色。
- 普通文本至少 4.5∶1，大文本至少 3∶1，识别控件或状态必需的图形对相邻底色至少 3∶1。星期、账户名、状态胶囊和支出金额按实际叠色后的前景与背景检查。[WCAG 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [WCAG 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 全应用的只读金额统一紧凑格式，覆盖账本、搜索结果、详情、账户、预算和报表。各显示位置沿用原有正负号含义，正负号、币种符号与数字之间均无空格。例如收入流水 `+¥10.00`、支出流水 `-¥10.00`、透支余额 `-¥12.34`、无方向的转账 `¥20.00`。收支小计等已由标签表达方向的金额继续显示为「支出 ¥10.00」。沿用各金额所属币种与两位小数约定（ADR-0004），在表现层映射或格式化处生成文字。
- 账本的折叠栏余额、概览、流水和小计均使用等宽数字（tnum）。可编辑金额框沿用现有输入与解析规则，CSV 导出及备份沿用各自的数据格式。

### 浅色组件配色

| 组件 | 无系统动态配色时的样式 |
| --- | --- |
| 月份、工具栏与概览 | 月份、流水标题和主余额用深灰绿 onSurface（`#191D1B`）；搜索、眼睛、跳转箭头和辅助标签用 onSurfaceVariant（`#424B46`）。月收入子容器用淡绿底 `#DAEDDF` 配深绿字与圆标图形 `#25392E`，月支出用淡珊瑚底 `#F9E5DF` 配深棕红 `#572D22`。 |
| 日期列与 FAB | 今日圆徽章与加号按钮共用 primaryContainer 浅薄荷绿底（`#C5ECDC`），日期数字与加号用 onPrimaryContainer 深绿（`#153E33`）。其余日期数字用 onSurface，星期用 onSurfaceVariant。 |
| 同日卡与金额 | 卡内分隔线用 outlineVariant（`#C4CEC7`），账户名用 onSurfaceVariant。流水与日小计沿用项目浅色收入青绿 `#0F766E`、支出赤褐 `#C2410C`；转账与余额用途金额用 onSurface。分类圆标取分类色的浅色调作底，前景按实际底色选可读色阶。 |
| 账单状态 | 待入账胶囊以同日卡为底，细描边用 outline，时钟与文案用 onSurfaceVariant。自动入账失败用 errorContainer 配 onErrorContainer，已跳过用中性文字和原有状态标记。 |
| 底部导航 | 选中项的实心图标用 onSecondaryContainer 深绿（`#263D34`），指示胶囊用 secondaryContainer 浅灰绿（`#D6E8DC`）。选中标签用 onSurface，未选中标签与线形图标用 onSurfaceVariant。 |

### 导航与概览

- 展开态月份组合紧凑居中，箭头跟随本地化年月的宽度，例如「‹ 2026年11月 ›」。工具栏右侧只放搜索按钮，所有图标按钮至少有 48 × 48 dp 独立热区。窄屏允许月份组合在可用空间内居中，优先保住热区和按钮间隔。保留点月份选月、左右滑月、折叠栏显示月份与余额、点折叠栏回顶。
- 概览顶行左侧为「全部余额」与 18–20 dp 眼睛图标，右侧为报表箭头。眼睛的提示与无障碍标签按状态显示「隐藏概览金额」或「显示概览金额」。隐藏时遮住全部余额、月收入、月支出及折叠栏余额，流水金额和日小计仍可读。点击卡片其余跳转区域打开所选月统计。主金额采用大号粗体等宽数字，使用当前主题的 onSurface（浅色模式为深灰绿，暗色模式为近白色）。折叠与展开遵循同一显隐状态。
- 底行扣除中缝后左右各占 50%，两块有色调的子容器使用相同内边距、左对齐标签与金额。标签随所选月更新，如「11月收入」「11月支出」，各配一个高对比度语义圆标。「全部余额」取当前账本币种纳入合计账户的实时余额，切月只改变月收入与月支出。
- 底部导航仅设「账本 / 预算 / 更多」三项，按此顺序排列。点资产概览卡进入所选月的统计报表，返回时回到原账本位置。导航栏采用 secondaryContainer 胶囊，选中的账本使用实心书形，未选中目的地使用 Lucide 线形图标；实心变体须能从轮廓辨认，延续现有图标造型。保留现有滚动收起、回滚恢复导航及切月恢复行为。
- 「更多」保留设置、账户管理、分类管理、帮助、反馈和关于入口。在设置页可备份与恢复，关闭设置后返回「更多」。

### 日期列、同日卡片与 FAB

- 复用现有按日吸附与惰性构建机制。日期列固定在 52–56 dp 范围内，与首条流水同顶；只有左栏日期吸附到工具栏下沿，同日内容继续滚动。下一组平滑顶替上一组，反向滚动沿同一边界交接；日期列保持现有行点击行为。相邻日卡外缘垂直距离为 12–16 dp。
- 星期用 onSurfaceVariant。仅本地日历中与今天同年、同月、同日的日期数字显示 primaryContainer 圆形徽章，数字使用 onPrimaryContainer。历史与未来日期沿用普通样式，入账状态由各行表达。
- 每天一张右栏卡，多笔间用极细 outlineVariant 线或轻量间隔。默认字号时每笔高 60–68 dp，左侧 36–40 dp 色调圆形图标，中央两行，金额靠右对齐。普通收支第一行优先显示备注，无备注时显示分类名称。第二行始终显示账户。例如，同一笔餐饮支出有备注时显示「早餐 / 现金」，无备注时显示「餐饮 / 现金」。移除独立分类文字胶囊，分类图标沿用交易的分类快照与项目图标映射。转账保留双方账户，期初余额、余额调整显示各自名称和无分类的用途图标。
- 暗色支出使用柔和珊瑚红（默认可用 #F2B8B5），浅色支出使用上表的赤褐色。收入使用对应主题的收入语义色。待入账标题保持正常对比，在账户旁用细描边胶囊显示时钟及「待入账」。失败及已跳过沿用各自文案、标记和详情操作。窄屏优先完整显示金额与状态。标题、账户名允许以省略号截断，点开详情可读全称。放大字号时允许状态胶囊换至下一行，行高随内容增长。
- 日小计的门槛是当天**可见记录数 ≥ 2**。满足门槛且有可计收支时，在卡片底部细分隔线下显示现有日分组提供的收入、支出，例如「支出 ¥10.00」。单笔或两项均无可计金额时，连同小计的线和留白一起省略。待入账、转账、两种余额用途、排除合计账户的流水可见，只影响条数，不贡献收支。
- FAB 的加号和背景分别使用 onPrimaryContainer 与 primaryContainer，默认暗色可用 #A6F2DC 和 #1F4E42。列表末尾至少预留 88 dp 可滚动内容空间，按 FAB 实际位置、底栏与系统安全区补足；验收依据是末条金额完整可见。空月份维持原有空态与滚动行为。
- 月份与新标签随英文、简体和繁体切换，英文 en 为本地化模板，基础中文 zh 回退文案与简体同步。

## Testing Decisions

用户已确认沿用现有页面测试。主入口为挂载真实应用路由的账本页，以现有 Riverpod 测试配置提供确定的月份和流水。验证用户能看到、点击或滚动到的结果，以及实际显示位置、命中区域和颜色对比。

| 场景 | 操作与通过条件 |
| --- | --- |
| 日期交接 | 准备相邻的单笔日和多笔日。向前拖到工具栏底、两日交界中点、下一日就位，再反向拖回。当前日期贴顶，两日期交接连续且无重叠；点日期栏所在行和右栏均能进入正确详情。只有今天的数字有圆形高亮。沿用现有时间线与换月测试。 |
| 密度与小计 | 默认字号测量日期列、行高、圆标与组间距。一天一笔支出无小计；一笔已入账支出 ¥10.00 加一笔待入账支出 ¥20.00 时仅显示「支出 ¥10.00」；两笔待入账无空小计。补测同日有收入和支出、转账与排除合计账户，复用日分组测试样例。 |
| 流水两行文案 | 同一分类、同一账户分别提供有备注和无备注的收支，核对首行显示备注或分类名，次行均为账户名。 |
| 跨页面只读金额 | 用同一笔支出依次查看账本、搜索结果和交易详情，三处均显示 `-¥10.00`。核对账户页的透支余额、预算与报表中的只读金额，按各自原有含义显示符号。检查负数的符号位置、无符号金额的首字符，以及收入流水的正号，均无多余空格。 |
| 状态与主题 | 用同一组流水分别验收默认浅色、动态浅色、默认暗色、动态暗色。核对四层表面，测量卡上金额、星期、状态胶囊、今日数字、FAB 和导航图标在实际底色上的对比度。用同一组动态色切换账本、预算和更多，核对各页表面角色。更换动态色时，今日徽章、FAB 和导航指示器随之更新，收入、支出及自选分类色仍可辨认。正常、待入账、失败、已跳过均可辨认。更新原先期望整行降透明度及分类胶囊的断言；沿用现有详情点击、记入与重试流程。 |
| 概览与导航 | 浅色和暗色底栏均恰好显示「账本 / 预算 / 更多」，依次点击可进入对应页面。切月并点概览箭头，核对报表月份及返回位置。点月份选择器、眼睛和搜索，核对所选月、实时余额、月收支、折叠后的掩码及搜索入口。点击「隐藏概览金额」，验证展开时三个数字与折叠时余额均被遮住，同一屏上的流水金额和日小计仍可读。再点「显示概览金额」可恢复。确认账本工具栏右侧只有搜索按钮。从「更多」进入设置，确认备份与恢复可达，返回后回到「更多」。沿用页头、导航滚动和设置路由测试。 |
| 窄屏与可访问性 | 在三种界面语言下检查月份组合与右侧搜索按钮各自可点，测试图标热区、概览两列等宽左对齐、带符号金额与状态文案。在窄屏放大字号，组合长账户名、「自动入账失败」和 -¥12,345.67，核对金额与状态完整且无溢出。标题、账户名若被截断，点开详情可读全称。 |
| 最末金额 | 在带底部安全区的窄屏滚到底，核对末条金额的完整边界位于可视区域内，且与 FAB、可见底栏均无交集。覆盖导航收起、恢复以及末日仅一笔的情况；空月份不因新增尾距而出现空滚动。 |

## Out of Scope

不重新设计预算、统计图表、交易表单、账单详情或备份流程。事件、投影、预约入账规则、金额精度、账户合计口径及持久化分类图标数据均沿用现有契约。

## Further Notes

实现时优先复用已有的报表入口、按日分组模型与滚动测试。三个判断须分别取值：日期徽章看本地今天，小计是否占位看可见条数和可计收支，金额是否计入看入账状态、交易种类及账户的合计开关。
