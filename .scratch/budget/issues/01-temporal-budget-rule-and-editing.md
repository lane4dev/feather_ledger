# 跨月预算规则与编辑语义

Type: grilling
Label: wayfinder:grilling
Status: resolved
Triage: ready-for-human

## Question

预算配置在时间维度上如何表达「设定后延续到未来月份、历史月份保持当时记录」，以及编辑、复盘后调参、清空、分类新建与分类归档时应遵循什么精确语义？

## Context

Chart 阶段已锚定：
- 不采用改一处污染全部历史月份的单一全局模板；
- 不采用每月完全空白必须手动复制的纯独立月表；
- 采用 CRUD 豁免表存储预算规则，按 `Current currency` 与 `categoryId` 隔离；
- 复盘闭环要求支持从历史月复盘页直接微调「下月/后续月份」预算，同时严守历史月份真实记录不被事后改写。

本票需要锁定以下决策，直接决定数据表模型与编辑弹窗行为：
1. **时间轴模型二选一（或变体）**：
   - 方案 A：**分段生效时间线（Effective-from 月份步进函数）** —— 记录 `(currencyCode, categoryId, effectiveYearMonth, amountMinor)`；查询某月 `M` 时取 `effectiveYearMonth <= M` 的最新一条记录；编辑某月 `M` 时可选择「仅本月」vs「本月及以后（同时决定是否覆盖未来已存在的更高月份条目）」。
   - 方案 B：**基线默认规则 + 单月覆盖（Baseline + Monthly Override）** —— 每个 `(currencyCode, categoryId)` 至多有一条默认额度 + 若干指定 `(year, month)` 的例外覆盖；编辑时问「仅本月」还是「设为默认月度预算（需明确是否会回溯改写未覆盖的历史月份！）」。
2. **「清空 / 取消预算」与「预算设为 0」的区分**：
   - 将已设预算的分类删掉/清空时，是从该月起恢复为「未设预算」（从「已设预算」分组移出，仅当有实际支出或待入账时才在未设预算区出现），还是允许显式设置 `0` 预算？
3. **跨月编辑与复盘调参入口边界**：
   - 过去月份（`< 当前自然月`）是否允许直接补设或修改预算（还是建议通过「调整从本月/下月起生效」为主、允许修正历史误设）？未来月份（`> 当前自然月`）是否允许提前设定预算？
4. **分类生命周期联动**：
   - 新建支出分类时：默认「未设预算」。
   - **归档分类**（`CategoryArchived`）：归档后是否自动从归档次月起停止延续预算（仅保留历史已生效月的预算记录与复盘结果），避免已归档分类继续出现在未来月份的「已设预算」列表里？若之后取消归档（恢复分类），预算是否自动恢复延续还是视为未设预算？
   - 注意：`CategoriesDao.watchCategoriesByType` 过滤 `archived == false` 与 `systemCode == null`；`categories_view` 保留已归档分类行。

## Answer

经两轮决策，本票锁定以下跨月预算规则与编辑语义：

1. **分段生效时间线模型（Effective-from 步进函数）**：
   - 每个 `(currencyCode, categoryId)` 维护一条按起始年月 `effectiveYearMonth` 递增的步进时间线；值域为 `{正整数金额 (> 0), unset (未设预算)}`。
   - 查询任意月份 `M` 时，取满足 `effectiveYearMonth <= M` 的最新一条记录（受下述分类归档截止规则约束）。
   - 编辑、新增或取消任意月份 `M` 绝不回溯改写 `< M` 的历史月份，严守历史复盘数据的真实性。

2. **双作用域编辑与取消语义（「仅本月」 vs 「本月及以后」）**：
   - **值域与 0 元预算**：有效预算金额必须严格 `> 0`（不允许 `0` 元预算）；清空/移除预算即设置状态为 `unset`（未设预算）。
   - **「仅本月」（`thisMonthOnly`）**：仅作用于月份 `M`；`M+1` 月自动保留/延续进入 `M` 之前原本生效的状态（若 `M+1` 本身已有显式断点，则保留 `M+1` 原断点不受影响）。
   - **「本月及以后」（`thisAndFollowing`）**：从月份 `M` 起生效并**覆盖所有 `> M` 的已存在更晚断点**（清理未来更晚断点，使 `M` 及之后区间统一为当前设定值或 `unset`；若存在将被覆盖的未来断点，界面提前提示确认）。
   - **取消预算同构**：取消/清空预算同样纳入时间线值域，支持「仅本月取消」与「本月及以后取消」。
   - **低摩擦智能默认**：
     - 在**当月或未来月**对「当前及之后均未设过预算」的分类**首次设预算**时，默认直接按「本月及以后」生效，免弹窗打断；
     - 其余场景（修改已有/延续预算、取消预算、存在更晚未来断点、或在**历史月 `< 当月`** 新增/修改/取消）提供「仅本月 / 本月及以后」作用域选择（历史月默认高亮「仅本月」，当月/未来月默认高亮「本月及以后」）。

3. **全时间轴可读可编辑与复盘调参引导**：
   - 过去月、当前月、未来月均允许查看与编辑/补录预算。
   - 在**历史月复盘视图**触发调整预算时，主引导动作为「调整从当前月/下月起生效」（复盘调参闭环），同时保留对历史当月预算做二级修正的能力（供补录或纠偏）。

4. **分类生命周期联动**：
   - **新建支出分类**：初始状态为 `unset`（未设预算）。
   - **归档分类（`CategoryArchived`）**：以 `CategoryArchived` 发生时的自然月（`EventEnvelope.recordedAt` 所在年月）作为**归档月**：
     - `<= 归档月` 的历史月份保留当时生效的预算与支出供复盘（UI 标注「已归档」）；
     - 从 **归档次月（`> 归档月`）** 起，无论之前是否存在延续规则或更晚预置的未来单月预算，查询层一律视为无延续预算（自动停止延续、不再计入总预算、不再出现在「已设预算」区；归档后若仍存在历史遗留消费/待入账，仅按无预算实际发生额展示）。
   - 已归档分类禁止新设预算；若未来代码库新增反归档能力，恢复后的分类默认状态为 `unset`。
