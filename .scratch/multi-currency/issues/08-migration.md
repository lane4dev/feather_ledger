# 如何验证新模型的数据完整性与备份恢复
Type: grilling
Label: wayfinder:grilling
Status: open
Blocked by: 04, 05, 06, 07, 16

## Question

在不要求兼容新模型上线前数据或旧备份的前提下，如何验证新模型的事件重放、可重建投影、不可重建周期表、备份恢复、中断和失败回滚？上线后产生的数据如何安全演进？

## Context

当前货币偏好保存在 SharedPreferences，周期系列和实例在 SQLite，二者不能直接共享 SQLite 事务。拟新增的币种切换、自动入账开关和实例处理资格可能跨越两个持久化位置：应评估中途崩溃、新模型备份恢复和重试的可恢复性，而非假设多次写入原子完成。具体采用集中存储还是恢复协议仍未决定。

用户明确表示没有需要保留的旧数据，不考虑旧数据兼容性；这不免除新模型上线后对用户数据、事件重放和备份的保护，也不授权现在删除或重置数据。

用户确认：三个自动入账开关只属于本机设置，不写入备份；恢复保留目标设备上的开关，新安装默认全部关闭。账单资格与待确认批次仍随备份保存。恢复后仅当目标设备相应开关开启且有符合条件的当前币种逾期账单时，才提示用户选择；不能直接运行现有启动补记。

- 用户确认：恢复时目标设备某类开关已关闭，该类型备份中既有的待确认批次仍保留；用户以后开启开关时再询问。这是“关闭开关会让待确认账单转手动”的例外：恢复时已经关闭不等同于恢复后主动关闭。
- 用户确认：恢复时目标设备某类开关已关闭，该类型其他尚未入账的逾期账单转为手动，以后开启也不自动补记。包括此前已同意但尚未成功入账且不在待确认状态的逾期账单。

- 用户确认：对话框展示币种、账单数量和日期范围；同一批次中当前满足币种、开关等条件的成员可一次确认。后续确认既有延期批次与本次新发现的账单分别询问，不能合并。
- 用户确认：对话框显示期间新到期的账单不纳入此次确认；符合条件的此类账单在下次启动处理。本次确认的账单范围需固定，使展示的数量、日期范围和实际处理对象一致。
- 用户选择“不自动入账”时，提示所涵盖的符合条件逾期实例全部转为手动处理，后续重启也不自动入账。
- 用户同意后，单笔失败不阻止其他账单处理；失败项保持待入账，也可手动处理。只要仍符合自动入账条件，下次启动自动重试，无需再次询问；已成功记入的实例不得重复记账。
- 用户确认：提示出现后没有作出选择就退出或进程中断时，先不自动入账；下次启动时在币种及本机开关满足条件后重新询问。恢复确认状态与已成功记入的实例须可恢复；具体持久化机制尚未确定。
- 用户确认：可关闭恢复提示并继续使用应用；本批次账单在用户作出决定前不得自动入账，下次启动在币种与开关符合条件时重新询问；其他新到期账单仍按正常规则处理。
- 用户确认：延期期间如果账单被手动记入或删除，再次提示时重新检查原批次，只展示仍待入账且仍符合自动入账条件的账单。
- 用户确认：恢复确认延期期间从美元切换到人民币，原本等待确认的美元逾期账单保留待确认状态，切回美元后再次询问。这是币种切换通常将到期未入账账单转为手动规则的明确例外；是否仍符合其他自动入账条件另行判定。
- 用户确认：延期期间关闭某类型的自动入账开关，该类型待确认逾期账单转为手动处理；重新开启也不自动补记。
- 用户确认：延期后切回有待确认账单的币种时，若相应本机开关开启则立即再次提示，不等待下次启动；关闭时保留恢复时已关闭开关对应的待确认项，开启后再询问。提示前重新检查原批次，只包括仍待入账且当前符合条件的实例。
- 用户确认：恢复确认延期只阻止原批次账单自动入账；延期后新到期的当前币种账单仍按正常资格规则在下次启动处理，无需等待原批次决定。
- 用户确认：新模型备份中若包含此前延期的自动入账确认批次，恢复后保留原批次和待确认状态，重新检查其中仍符合条件的账单后询问；不能静默丢弃或视为已经同意。
- 用户确认：同一份备份中既有此前延期的确认批次，也有本次恢复时新发现的其他符合条件逾期账单时，旧批次与新发现的账单分别确认，不能合并成一次决定；各批次的数量、日期范围和决定各自保存。
- 用户确认：用户暂时关闭旧批次提示后，仍可分别提示和处理新批次；旧批次继续等待确认，各批次互不阻塞。
- 代码核对：启动流程在恢复备份和导入偏好后会调用现有 `catchUpAutoPosted`；恢复确认必须在任何自动入账入口之前建立持久的待确认屏障，即使进程中断后重启也不能绕开。账户解除归档同样存在自动入账调用，须一并纳入控制。
- 用户确认：备份生成时尚未到期、但在生成备份与恢复之间到期的实例，在目标设备当前币种及相应自动入账开关满足条件时，纳入恢复确认；用户同意后才自动入账。备份中既有的永久手动、已入账、已跳过和待确认批次等状态仍按各自规则处理；不能从备份推测生成后来源设备的真实状态。
- 用户确认：恢复确认批次已同意后，尚未处理的某笔账单被用户修改金额时，该笔转为手动处理；批次中的其他账单照常处理。这与未被用户修改但处理失败、仍符合条件时可下次自动重试的既定规则不同。
- 用户确认：恢复确认尚未作出选择时，用户修改某笔账单金额；若该账单仍已到期且符合当前币种及开关条件，它仍保留在待确认批次，重新检查后由用户决定。
- 用户确认：用户同意恢复批次后，尚未处理的某笔账单只要实际修改金额、日期、账户、分类或描述中的任一字段，该笔转为手动处理；批次中其他未发生实际修改的账单照常处理。这不改变未修改但入账失败的账单在仍符合资格时可重试的既定规则。
- 用户确认：恢复批次未决定前，若某成员改期到未来，保留其原批次待确认资格；按新日期到期后，在币种及开关等条件满足时再次询问。它尚未到期时不应计入当前可确认成员的数量或日期范围，既定的开关关闭等资格规则仍适用。
- 用户确认：恢复确认对话框显示期间，候选账单的金额或其他账务字段发生实际变化，即使数量和日期范围不变，也要刷新确认状态并要求用户重新确认，不能沿用旧确认。
- 用户确认：恢复确认应提示备份生成之后其他设备的记账不会同步，用户需核对是否重复；该提示和确认不提供跨设备去重。

- 备份内已有的订阅规则，在备份后至恢复前到期、但备份时尚未物化的实例，符合条件时也纳入恢复确认；恢复确认候选的生成和完整性必须覆盖这些实例，不能仅扫描备份中已有行。较早期次失败或转为手动时，继续处理后续合格期次，各结果分别统计。
