# 多币种任务拆分草案

状态：待用户审阅；本文件是拆分提案，不是已发布任务。依据同目录的需求规格及决策地图。原有 01–16 是决策和研究票，保留原样；建议实施票从 17 起编号，避免引用冲突。每张实施票最终单独发布到工单目录。

## 安全交付约定

各票包含从用户可见行为到存储和验证的完整路径。自动入账、恢复与通知的改动应在集成分支或受控开关下交付：未完成相关安全前置能力时，自动入账保持关闭，不能让中间版本绕过恢复确认、错误记账或丢失数据。各票以公开服务及必要的界面、平台适配边界验证行为，沿用领域模型与既有事件/投影架构。新模型前数据兼容不在范围，但任何阶段都不授权删除或重置现有数据。

## 第一阶段：币种与账户

### 17. 初始化并保存当前币种

**依赖：** 无。

**交付：** 首次使用按系统语言确定币种，之后从设置修改并持久化，账本使用同一选择。

**验收条件：**

- [ ] 中文 CNY、日语 JPY、英语 USD、德语/法语 EUR，其他语言 USD；不根据地区覆盖映射。
- [ ] 五种币种可选；重启和系统语言变更不覆盖已保存选择。
- [ ] 新模型备份与恢复保留币种选择；不会重置现有数据。
- [ ] 测试覆盖首次初始化、保存、重启、恢复和不受支持语言。

### 18. 创建和管理独立币种账户

**依赖：** 17。

**交付：** 账户创建时选币种，管理页可查看其他币种账户与调整其余额。

**验收条件：**

- [ ] 创建默认当前币种，可改选五种币种；保存后账户币种不可修改。
- [ ] 管理页默认当前币种，可局部筛选其他及全部币种；混看显示符号和代码，不混币求和。
- [ ] 新建其他币种账户后局部筛到该币种，不改变全局设置；调整其余额时显示正确币种及所在账本提示。
- [ ] 归档、排除合计保持各自原有语义；重启和事件重放保持账户币种及余额。

### 19. 同币种交易、转账和表单锁定

**依赖：** 18。

**交付：** 新建及编辑交易使用账户币种；表单和写入都阻止跨币种串账。

**验收条件：**

- [ ] 收支按账户币种记账；已入账交易编辑只允许改选原币种账户。
- [ ] 同币种不同账户可转账；选择器和直接服务调用均拒绝跨币种或同账户转账。
- [ ] 新表单打开时锁定币种，设置变化不清空输入、不重解释金额，账户选择和提交仍用原币种。
- [ ] 五种币种贯穿输入、事件、投影、显示使用每单位百分之一的整数及两位显示，包括 JPY；测试验证重放与数值一致。

### 20. 当前币种账本、头部与空状态

**依赖：** 18、19。

**交付：** 账本交易、待入账列表和日/月合计均限定当前币种，切换时不误标或混加。

**验收条件：**

- [ ] 查询和汇总前限定币种，不同币种同一天/同月份不混合；归档与排除合计规则仍正确。
- [ ] 有账户无交易时显示余额、零收支及带币种名称的空状态；无账户时显示零合计并引导创建账户。
- [ ] 快速切换、异步返回及相邻月份缓存不将旧币种数据标为新币种。
- [ ] 包含跨重启、不同币种同符号及待入账筛选的服务和界面测试。

### 21. 当前币种搜索与报表

**依赖：** 17、18。

**交付：** 搜索、分类报表和热度图按设置中的当前币种查询并安全切换。

**验收条件：**

- [ ] 搜索与关键词、账户、分类、类型、日期组合时仍仅返回当前币种；账户管理局部筛选不影响搜索。
- [ ] 分类报表和热度图在聚合前限定币种，不提供独立币种切换；排除合计语义保持一致。
- [ ] 快速切换与异步结果不误标币种；未来导出契约限定当前币种和现有筛选并保留币种代码，本票不增加导出入口。

## 第二阶段：账单身份与自动资格

### 22. 账单模式和本机自动入账设置

**依赖：** 17、18。

**交付：** 创建计划、订阅及重复账单后能识别其原始模式；设置中分别控制三类自动入账。

**验收条件：**

- [ ] 创建时记录默认、计划、订阅、重复模式；已创建账单不可切换模式，普通字段仍可编辑。
- [ ] 三个类型开关各自默认关闭，独立控制已有及未来账单；设置不改变提醒或触发真实支付。
- [ ] 开关仅留本机，新模型备份不包含开关及其原始历史，恢复保留目标设备值；账本资格等数据仍可携带。
- [ ] 未具备资格和恢复保护前不可暴露不安全的自动入账路径；测试覆盖重启及恢复不同本机设置。

### 23. 自动资格、币种暂停与手动处理

**依赖：** 19、20、22。

**交付：** 当前币种和开关决定账单自动资格，已逾期或暂停期间的账单可靠保留手动处理。

**验收条件：**

- [ ] 离开币种或关闭对应开关时已逾期未处理的期次，以及暂停/关闭期间到期的期次转为永久手动；重新开启或切回不自动补记。
- [ ] 开启或切回与到期同一毫秒、创建已逾期或改期至过去的普通账单按手动处理；可检测的不可靠时间回拨也转手动。
- [ ] 到期前修改未来普通账单金额或描述保留原有资格；到期未处理后实际更改金额、日期、账户、分类或描述转手动，无变化保存不误转。
- [ ] 手动资格跨重启、单期改期及新模型备份恢复保留；恢复待确认批次的例外由后续恢复票实现，当前安全屏障不可绕过。
- [ ] 自动入账只在启动补记或经用户同意的恢复批次发生；现有其他调用路径不能绕过统一资格检查。

### 24. 逾期账单按月补齐和本地时区

**依赖：** 20、23。

**交付：** 长期未启动产生的历史账单能按原月份逐批找到，并按当地时区判断到期。

**验收条件：**

- [ ] 超过常规窗口上限的待处理期次可有界、可接续地生成并在原月份展示；月份选择器能标记尚未物化的待处理月份。
- [ ] 手动记入采用排定日期，无集中逾期列表；失败或手动期次不阻塞后续期次，跳过不产生交易。
- [ ] 晚物化期次按规则生效和到期时的条件判断，不因实际行生成较晚而自动变手动。
- [ ] 跨时区后遵循当前当地时间，夏令时缺失时间顺延拨钟时长、重复时间取第一次；已确定状态和逻辑身份不变。
- [ ] 覆盖无限、有限次数和结束日期系列，以及长期关闭、时区变化和恢复后分页。

### 25. 同频率系列改期、稳定期次与次数

**依赖：** 23、24。

**交付：** 整条或本次及以后改期时，原账单资格、对应关系和次数不丢失、不重复。

**验收条件：**

- [ ] 范围内手动期次移动后保持手动；已入账交易保留原日期且不生成对应新账单；范围外不变。
- [ ] 周、月、年按规格的自然周期及用户所选日期锚点对应；月末不存在的日期不会按生成顺序错配。
- [ ] 无对应新日期的手动期次保留原日期；新规则新增过去期次不补造；再次改期同一期同日只留一笔手动账单。
- [ ] 有限次数上限不变；已入账及保留的手动期次计数，单期删除释放次数并在末尾补期，新期独立判资格。
- [ ] 系列拆分、反复改期、删除及物化可幂等恢复；不改变既有实例 ID 形状及日期归一化，未确认的其他频率边界不凭空决定。

## 第三阶段：补记与恢复

### 26. 后台可续的启动补记与批次进度

**依赖：** 23、24。

**交付：** 合格账单在启动后分批记入，用户可继续使用应用并查看各批次结果。

**验收条件：**

- [ ] 先进入应用，再按固定启动截点分批处理；前台之后新到期期次留待下次启动，账本逐步更新。
- [ ] 每批独立展示自动成功、失败、用户已处理、转手动数量；每期每批仅有一个当前结果。
- [ ] 失败不阻断其他期次并留在原月份可重试或手动处理；重试成功、手动记入或删除更新原批次结果。
- [ ] 系统中断重启后接续原批次并保留累计结果；新到期者另建独立批次，事务和幂等防止重复入账。
- [ ] 处理途中用户手动处理或实际修改账单时按提交顺序正确归类；后台运行尽力继续，不承诺系统存活。

### 27. 安全恢复与恢复批次确认

**依赖：** 22、23、24、26。

**交付：** 从新模型备份恢复后，用户能分别确认合格逾期账单，任何恢复或中断路径均不会绕过确认。

**验收条件：**

- [ ] 目标设备开关不被备份覆盖；恢复建立可持久化确认屏障后才允许任何自动入账，崩溃和重试不产生部分恢复或误记。
- [ ] 备份生成后、恢复前到期且合格的账单纳入确认，包括备份中尚未物化但能从规则推导的期次；不推测来源设备备份后的记账。
- [ ] 各批显示币种、数量、日期范围和跨设备不同步及可能重复提示；旧延期批次与新发现批次分别确认、互不阻塞。
- [ ] 拒绝使所展示期次永久手动；同意后逐期处理，失败不挡其他期次且符合条件时下次自动重试；未决定、关闭提示或中断时不自动入账。
- [ ] 恢复时已关闭开关的既有待确认批次保留，其他未入账逾期账单转手动；恢复后主动关闭开关使待确认逾期项转手动。
- [ ] 原批次可延期，切离币种保留、切回且开关开启立即重询；新到期正常账单不被延期批次阻塞。

### 28. 恢复确认期间的编辑与并发

**依赖：** 25、27。

**交付：** 恢复确认始终针对用户实际看到的账单内容，编辑和入账并发不会误记。

**验收条件：**

- [ ] 待确认期间手动记入或删除的不再列入候选；修改后重新检查，改到未来保留原批次资格、到期后再询问。
- [ ] 对话框期间任一候选账务字段实际变化，即使数量和日期范围相同也刷新并重新确认；显示期间新到期者不加入本次确认。
- [ ] 同意后、处理前实际修改金额、日期、账户、分类或描述，该期转手动，其余期次继续；无实际变化不误转。
- [ ] 修改与入账竞争时以原子提交结果判断，既不重复记账也不依据过期确认记账；覆盖中断与多批并存。

## 第四阶段：通知与事件重建

### 29. 币种切换时的账单提醒

**依赖：** 20、23、24。

**交付：** 非当前币种提醒暂停，保留已显示通知供用户处理原币种账单。

**验收条件：**

- [ ] 切换时取消旧币种未触发提醒，保留已显示通知；切回只安排未来提醒，不补发错过的提醒。
- [ ] 已显示通知可打开其他币种账单，显示其币种，可编辑或手动记入，仅能选原币种账户，全局设置不变。
- [ ] 自动或手动入账成功后取消未触发提醒；权限变化及调度失败不改变账本事实。

### 30. 旧通知追踪改期、更正和删除

**依赖：** 25、29。

**交付：** 用户点击历史账单通知时始终看到对应账单或最新交易的实际状态。

**验收条件：**

- [ ] 未入账账单改期、拆分或多次改期后，旧通知打开同一期最新日期；单期或整条系列删除后提示已删除。
- [ ] 已入账账单的旧通知打开最新交易并提示已记入；多次更正后仍能定位最新交易，交易删除后提示已删除且不重复记账。
- [ ] 新交易事件含来源账单和更正关联，重建投影后可恢复追踪；必要的精简删除记录随账本保留并经新模型备份恢复。
- [ ] 含中断、通知重复点击、系列删除和投影重建的服务及通知适配测试。

## 第五阶段：集成验收

### 31. 新模型跨场景恢复与发布门禁

**依赖：** 20、21、26、28、30。

**交付：** 验证所有已交付路径共同满足多币种规格，解除受控交付限制。

**验收条件：**

- [ ] 执行端到端场景：多币种记账和合计、快速切换、超过窗口的历史账单、改期去重、恢复确认、通知与交易更正。
- [ ] 新模型备份恢复、事务中断及事件投影重建后，币种、余额、周期账单、资格、批次和通知关联一致；本机开关保留。
- [ ] 完成规格定义的分析与相关自动化测试，记录平台通知协调限制及任何未覆盖的已确认场景；缺陷关闭前不解除保护。
- [ ] 不引入汇率、跨币种转账、原生精度迁移、CSV 入口或对新模型前数据的删除操作。
