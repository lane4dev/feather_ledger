# 多币种方案：关键验收场景

这些是已确认规则的具体例子，用来检验后续规格、原型和实现；它们不是已通过的代码测试。若实现方案不能覆盖这些例子，不能仅凭界面展示宣布完成。

| 场景 | 预期 |
| --- | --- |
| 账本有 CNY 和 USD 账户，设置为 CNY | 账本和统计只读取 CNY；其他币种账户可在账户管理通过筛选查看；不同币种不得直接相加。 |
| 新建账户时设置为 CNY，用户选 USD | 账户记为 USD，后续改变设置不改变该账户币种；同币种转账可用，跨币种转账拒绝。 |
| 自动开关 09:00:00.000 开启，账单同一毫秒到期 | 该期保留手动；不能靠相同时间戳猜测先后。 |
| 自动开关开启后，新建一笔到期时间已过去的计划账单 | 该期保留手动；不能仅依据到期时间晚于开关开启时间就自动入账。 |
| 未来账单在到期前修改金额，日期仍在未来 | 普通账单保留自动资格，按新内容处理；已有手动或恢复确认限制不被覆盖。 |
| 普通未来账单改期到修改时已过去的日期 | 该期留待手动，不因旧的自动资格而补记。 |
| 每月 1 日的系列整体改到 3 日，某期原本是永久手动账单 | 对应期次移至该月 3 日并保持手动，不额外保留该月 1 日的旧账单。 |
| 每月 1 日的系列整体改到 3 日，某期已经入账 | 已入账交易保留原日期；平移后的对应期次不再生成待入账账单。 |
| 启动后补记 100 笔，处理期间用户先手动记入一笔、修改一笔 | 被手动记入的一笔计入用户已处理，修改的一笔转手动；其他账单继续，不重复记账。 |
| 补记过程中系统终止，重启后有额外账单新到期 | 原批次按持久状态接续；新到期的其他账单单独建批次；原批次累计结果不重复计数。 |
| 批次结果为成功 9、失败 1；失败项后来重试成功 | 原批次更新为成功 10、失败 0；同一成员不同时计入成功和失败。 |
| 批次结果为成功 9、失败 1；失败项后来被用户手动记入 | 原批次失败数减一、用户已处理数加一；不计为自动成功。 |
| 恢复前的备份保存时账单尚未到期，恢复时已到期且目标设备条件满足 | 纳入恢复确认，同意后才处理；备份中已有的手动、已处理和待确认状态不被覆盖。提示备份后其他设备的记账不会同步，需核对是否重复。 |
| 恢复批次尚未决定时，用户把成员改到未来 | 保留原批次待确认资格；尚未到期时不计入当前可确认成员，到期且条件满足后再询问。 |
| 恢复确认框显示期间候选金额变化，数量与日期范围不变 | 刷新确认状态并要求重新确认；不能只用数量与日期范围判断是否变化。 |
| 恢复批次已同意，一笔尚未处理的成员被实际修改账务字段 | 该笔转手动，其他未变化成员继续；修改与入账并发时按原子提交结果处理。 |
| 已显示通知对应的未入账账单被删除一期或整个系列 | 精简删除记录随账本保留；点击旧通知显示“已删除”，不重新记账。 |
| 已显示通知对应账单入账后，交易多次更正或删除 | 关联从新事件重建；更正后打开最新交易，删除后提示已删除且不再记账。 |
| 账单设置为当地 09:00，设备跨时区或遇到夏令时变化 | 按已确认的当地时间及夏令时规则确定将来到期时刻，逻辑期次身份、完成状态和永久手动资格不改变。 |
| 设备时钟回拨且可检测到资格先后无法可靠判断 | 受影响账单留待手动；不承诺检测到所有应用关闭期间的时钟调整。 |

技术方案仍需单独验证恢复中断、有限和无限规则的有界展开、稳定身份以及通知平台协调，详见[可实施性审查](engineering-feasibility-review.md)。


### 同频率改期的补充决策

- “本次及以后”改期时，修改范围内原本须手动处理的对应期次移动后仍须手动；已入账期次保留原交易，不生成对应的新待入账账单。范围之前的账单不变。
- 新规则多出的已过去期次不补造，未来期次按新规则生成。例如无限期系列每月 31 日改为 30 日，若编辑时已到 5 月，不补造原先不存在的 4 月 30 日账单。
- 期次对应关系不能仅按生成序号匹配：月末不存在的日期会被重复规则跳过。实现需明确匹配规则、持久化必要状态并覆盖月末及拆分场景；不能改变现有实例 ID 的格式和日期归一化。上述为设计与验收要求，尚未实现或执行测试。
- 用户确认月度期次按月份、年度期次按年份对应，不按生成序号；若新规则在该自然周期没有对应日期，已有手动账单保留原日期并继续手动。例如 30 日改为 31 日时，保留原 4 月 30 日手动账单。月度跨月改期以用户选中的原账单和目标日期作为对应锚点，其余期次按相同月份偏移对应；例如 3 月 31 日改为 4 月 2 日，原 3 月期对应 4 月 2 日。每周期次以周一至周日为自然周，跨周编辑以选中的原日期与目标日期为锚点，其他期次按相同周偏移；年度跨年也以所选日期为锚点，按相同年份偏移。其他频率及边界仍需明确。
- 此后同系列再改期，新规则期次与之前保留的手动账单同日时视为同一期，仅留一笔手动账单。有限次数系列保留原次数上限：已入账期次、因新规则没有对应日期而保留的手动期次占用次数；用户仅删除一期则不占用次数，在系列末尾补一期。应覆盖规则跳过无效日期、墓碑与系列拆分；现有 RRULE COUNT 和跳过状态不能直接等同于有效次数，需设计计数及有界物化。
- 已显示通知所对应的未入账账单改期后，点击旧通知应解析到同一账单的最新日期；需持久化稳定关联并覆盖多次改期、系列拆分和恢复，不能只依赖日期编码的实例 ID。删除有限次数系列的一期后补出的新期，依据新期自身的创建时间、到期时间及当时条件独立判定自动入账资格，不继承删除期资格。
- 长期离线后，实例即使在到期后才物化，也按规则生效时间和到期时满足的自动入账条件判断，不能仅因物化晚于到期就转手动。对启动截点前尚未物化的历史到期实例持续有界地分批生成和处理、显示进度；需可接续的游标及幂等处理，失败/手动项不能让后续期次饿死。不得将常规滚动窗口的 3–12 条上限误当成历史补齐的总上限。

- 备份内已有的订阅规则，在备份后至恢复前到期、但备份时尚未物化的实例，符合条件时也纳入恢复确认；恢复确认候选的生成和完整性必须覆盖这些实例，不能仅扫描备份中已有行。较早期次失败或转为手动时，继续处理后续合格期次，各结果分别统计。
