# 周期性记账与预算的混合投影架构（Hybrid Recurring Projection）

## Problem Statement

在个人记账与月度预算规划中，用户经常同时管理高频周期支出（如每日通勤、每周采购）、中低频固定账单（如每月房租、年度订阅）以及一次性计划支出。当前账本为了防止待入账列表与本地通知队列无界膨胀，仅对活跃周期规则执行有限窗口的物理物化（当月及未来 1 个完整自然月，外加低频规则保底 1 期）。

当用户在预算页面切换到超出物理物化窗口的远期月份进行规划（Plan 模式）时，尚未物化的周期支出如果仅依赖物理待入账表统计，会导致远期月份的**待入账敞口（Pending bill exposure）**与**固定支出基线（Committed spend）**断崖式归零，使预算规划失去参考依据；同时，如果为了远期预算而把物理物化窗口拉长到一两年，又会向本地数据库写入大量高频冗余账单行，拖累日常记账与账本查询体验。

此外，在混合投影已部分落地的现状下，仍有两类边界风险会影响用户体验与口径一致性：一是用户翻看极远未来月份时，高频规则缺乏前瞻上限保护可能引发明显卡顿；二是已归档分类在归档月之后仍可能把虚拟待入账混入全月待入账总额或记账表单提示条，造成与预算时间轴（Budget timeline）截断规则不一致。

## Solution

建立并收口一套**混合投影架构（自然月近期物理物化 + 预算读时虚拟补齐 + 按需落库）**：

1. **近期物理物化保持有界**：账本写入与待入账列表继续维持自然月对齐的三阶段物理物化（覆盖当月与未来 1 个完整自然月，低频保底 1 期，历史回填有界），确保日常账本列表清爽、提醒数量可控。
2. **预算读时统一虚拟补齐**：在追踪当月（Track）与规划未来月（Plan）时，预算首页、分类详情页与记账表单的实时预算提示条共同消费同一套混合待入账口径——将物理待入账账单与基于统一日历引擎按月展开的虚拟期次合并，并严格以原始发生身份去重，确保单期改期跨月、单期改额、跳过与提前入账全部不重不漏。
3. **远期虚拟账单可交互**：在预算分类详情中展示远期虚拟待入账项，用户点击时按需原子落库为标准待入账账单，直接复用既有的记入、单期编辑与跳过流程，无需额外学习一套“只读摘要”心智模型。
4. **补齐边界护栏**：对虚拟补齐施加合理的前瞻上限与步进性能保护，并统一归档分类在归档月之后的截断口径，确保所有预算视图、分类提示与总览数据完全一致。

## User Stories

1. 作为记账用户，我希望在预算页查看当月（Track）时，每日、每周、每月等所有活跃周期支出的当月全部期次都准确计入待入账敞口与固定支出基线，以便准确判断本月剩余可用预算。
2. 作为记账用户，我希望在预算页切换到次月（Plan）时，能看到完整的固定支出基线与待入账明细，以便提前安排下月分类预算。
3. 作为记账用户，我希望在预算页切换到未来第 2 个月及更远月份（超出近期物理物化窗口）进行中长期规划时，依然能看到所有活跃周期支出的完整月度预计金额，而不是固定支出基线突然归零。
4. 作为记账用户，我希望在远期规划月中，不需要看到“仅统计已生成周期账单”之类的免责提示，系统给出的预计剩余预算就是完整可信的。
5. 作为记账用户，我希望在预算页查看历史月份（Review 模式）时，系统严格以实际支出（Actual）评估预算达标情况，不把任何虚拟周期期次混入历史月份。
6. 作为记账用户，当我把某一期原定本月底的周期账单通过单期改期（`thisOnly`）推迟到下月初时，我希望本月的待入账敞口减少这一期、下月的待入账敞口增加这一期，且本月不会因为虚拟补齐而把原日期重新算回来。
7. 作为记账用户，当我把某一期账单改期到下月某一天，而该系列在下月同一天原本也有一期规则账单时，我希望下月能同时正确统计这两笔账单，互不覆盖。
8. 作为记账用户，当我把某一期周期账单覆写为不同金额（单期改额）时，我希望预算仅对该期使用覆写金额，而同系列其他物理期次和远期虚拟期次仍按规则原金额计算。
9. 作为记账用户，当我跳过（Skip）某一期周期账单时，我希望该期从预算待入账敞口中消失，并且绝不会因为虚拟补齐而“复活”。
10. 作为记账用户，当我把某一期周期账单提前手动记入（Post）成为正式交易时，我希望该笔金额只出现在实际支出（已承诺支出）中，绝不会同时被虚拟补齐重复计入待入账敞口。
11. 作为记账用户，当我为周期规则设置了结束日期（`endDate`）后，我希望结束日期之后的未来月份不再出现该系列的虚拟待入账。
12. 作为记账用户，当我为分期或有限次周期规则设置了总次数上限（`countLimit`），且中途修改过规则排期时，我希望虚拟补齐严格遵守全生命周期剩余次数，总期数绝不超过上限。
13. 作为记账用户，当我创建了一条起点在较早过去的周期规则并选择“仅从今天起生成”时，我希望虚拟补齐同样尊重起始物化下界（`materializeFrom`），不会把下界之前的历史期次算进当月或历史月。
14. 作为记账用户，当我停用（Stop）一条周期规则后，我希望它不再出现在任何未来月份的预算虚拟补齐中，而历史已入账交易的固定支出归类保持不变。
15. 作为记账用户，当我将某个账户设置为“不计入账本合计（`includeInTotals = false`）”时，我希望挂在该账户下的周期支出不计入任何月份的预算实际支出与待入账敞口（含虚拟期次）。
16. 作为记账用户，当我归档一个账户后，我希望其已停用的周期规则不再产生未来虚拟待入账，而归档时保留为一次性计划账单的逾期未处理项在归档前/当月仍能按既有物理待办口径呈现。
17. 作为记账用户，当我归档一个支出分类后，我希望该分类在归档当月仍保留其有效预算与待入账统计，但从归档月的下一个月起，不再对该分类执行预算结转，且该分类的物理待入账与虚拟待入账一并从全月待入账汇总与单分类提示中排除。
18. 作为记账用户，我希望收入类型的周期规则和转账永远不会被混入预算的支出待入账敞口中。
19. 作为记账用户，我希望切换当前币种（Current currency）后，预算页与记账提示条仅聚合当前币种下账户的周期支出，绝不跨币种混算。
20. 作为记账用户，我希望在记账表单中录入一笔新支出并选择分类与日期时，实时预算提示条显示的“预计剩余”与预算首页、分类详情页在同一月份下的数字 100% 一致（包含远期虚拟待入账）。
21. 作为记账用户，我希望在远期规划月的预算分类详情页中，可以直接点击某一条尚未物理落库的虚拟待入账，并在打开账单操作面板后完成单期改期、改额或跳过，操作体验与近期物理待入账完全一致。
22. 作为记账用户，当我快速连续点击同一条远期虚拟待入账时，我希望系统幂等处理，不会生成重复的物理待入账行。
23. 作为记账用户，当我把预算月份切换到非常遥远的未来（例如超过 24 个月以后），即使账本中存在每日重复的周期规则，我也希望页面依然流畅响应，不会出现卡顿或无响应。
24. 作为记账用户，我希望日常账本页（`/ledger`）翻到物理物化窗口之外的未来月份时，也能看到周期收入与支出的虚拟待入账期次，并且点击后可幂等落库再进入既有账单操作面板；同时这些虚拟项不得进入每日收支小计、余额、提醒红点或搜索/报表。

## Implementation Decisions

- **保持两层混合投影职责边界**：
  - **层一（物理物化）**：`ProjectRecurringEventsCommand` 维持三阶段自然月对齐物化（Phase 0 历史回填最多 12 个自然月且单系列上限 100 条；Phase 1 完整物化当月 + 未来 1 个完整自然月，安全阀 120 条；Phase 2 低频保底 1 期；一次性 `planned` 系列幂等生成 `'single'`）。不做无界远期物理写入，不改动 CRUD 豁免边界，也不新增数据库表或 schema 迁移。
  - **层二（预算与账本读时虚拟补齐）**：仅在 `nowYm <= targetYm <= nowYm + 24` 时启用。预算由 `WatchMonthBudgetQuery` / `WatchTransactionBudgetHintQuery` 判定 `includeVirtual`，历史月（Review）关闭；账本由 `WatchMonthlyPendingBillsQuery` 判定，历史月与超出 24 个月的未来月关闭。两条读路径共用 `RecurrenceExpander` 与 `(seriesId, occurrenceKey)` 去重集合。
  - **预算与账本口径差异**：预算虚拟项只含支出且要求账户 `includeInTotals`；账本虚拟项包含收入与支出、忽略 `includeInTotals`，但同样排除已归档/已删除账户。`pendingBillMonths`、本地提醒、余额、快照、每日小计、趋势、搜索与报表继续只读物理表。
- **单一周期推演引擎**：
  - 所有周期日期展开（物理物化、预算虚拟补齐、按需落库校验）统一通过共享领域引擎 `RecurrenceExpander` 及其值对象 `RecurrenceRuleSpec` 执行。
  - 推演全程基于无时区偏移的本地日历日（local civil date），再拼回规则本地时刻，杜绝 UTC 午夜偏移、夏令时小时漂移与 `BYDAY` 星期偏移。
- **去重不变量（ADR-0005 对齐）**：
  - 虚拟补齐的唯一去重键为 `(seriesId, occurrenceKey)`，其中 `repeating` 系列为本地日历日 `YYYY-MM-DD`，`planned` 系列为固定键 `'single'`；严禁使用 `effectiveDate` 或时间戳去重。
  - 收集某目标月的已物化覆盖集合时，必须包含目标月对应 `occurrenceKey` 前缀（及 `'single'`）下**全部状态**（`scheduled`、`failed`、`skipped`、`posted`）的物理行，从而同时保证跳过不复活、提前入账不重复以及单期跨月改期不重不漏。
  - 物理未入账待办仍按生效日期 `coalesce(dateOverride, scheduledDate)` 落入目标月统计，并使用 `coalesce(amountOverrideMinor, series.amountMinor)` 与 `coalesce(memoOverride, series.description)`；虚拟补齐项使用规则原金额与描述。
- **按需落库（Materialize-on-Write）契约**：
  - 预算读模型为虚拟待入账项携带 `isVirtual = true`、所属 `seriesId` 与 `occurrenceKey`。
  - 当用户在预算分类详情页点击虚拟项时，表现层通过 `BudgetViewModel` 委托 `RecurringService.ensureMaterialized`（内部执行 `EnsureOccurrenceMaterializedCommand`）：在单次数据库事务内校验系列仍活跃、账户未归档且未删除、且 `(seriesId, occurrenceKey)` 合法匹配规则并满足 `materializeFrom` 下界，随后幂等 `INSERT OR IGNORE` 生成标准 UUID 的 `scheduled` 行并返回该实体，紧接着复用标准 `PendingBillSheet` 流程。
- **本次收口加固决策（已评审确认）**：
  1. **远期展开性能护栏**：在预算虚拟补齐入口明确引入最大前瞻上限（`nowYm <= targetYm <= nowYm + 24` 个自然月；超出上限的月份静默跳过虚拟补齐，仅返回物理待入账，不限制月份选择器本身、不新增 UI 提示文案），并对无 `countLimit` 约束的高频规则（`DAILY` / `WEEKLY`）在 `RecurrenceExpander` 内支持按周期步进快进至目标窗口附近，避免从很久以前的 `startDate` 线性空转。
  2. **归档分类截断统一（物理 + 虚拟一并排除）**：在待入账加载入口（`BudgetDao`）同时为物理待入账查询与虚拟补齐查询关联分类元数据，过滤掉系统分类（`systemCode != null`）以及已归档且 `targetYm > archiveYm` 的支出分类；确保预算总览的 `allExpensePendingMinor`、分类行待入账、贡献列表与单分类记账提示条（`watchCategoryBudgetHint`）在归档月之后保持 100% 一致的截断口径。
  3. **6 个月趋势图边界**：`BudgetCalculator` 仅在目标月 `m == targetYm` 填入 `pendingMinor`，趋势窗口内其余 5 个月保持 `pendingMinor = 0`，不做多月批量虚拟展开。
  4. **分层保持稳定**：本次聚焦行为与性能收口，不顺带将 `BudgetDao` 内的内存 Overlay 逻辑搬迁抽离为独立 `BudgetPendingProjector` 服务。

## Testing Decisions

- **好测试的标准**：
  - 测试只验证外部可观察的行为与业务不变量（如月度预算汇总的 `actual`、`pending`、`projectedRemaining`、`committedBaseline`、分类贡献列表、记账表单提示条数值，以及点击虚拟账单后落库得到的标准待入账实体），不耦合内部 SQL 语句结构、私有方法或临时数据结构。
  - 使用注入的 `DomainClock`（`FixedClock`）控制“当前月份”，确保跨月、闰年、月末边界与前瞻上限测试 100% 确定性。
- **推荐测试接缝（Seams）**：
  - **主接缝（最高服务层接缝，优先采用）**：以 `BudgetService` + `RecurringService`（经由内存数据库与 `LedgerServiceHarness`）作为单一高层集成接缝。通过真实命令写入周期系列、执行物化/单期改期/单期改额/跳过/提前入账/归档分类/归档账户/切换合计开关，再订阅 `watchMonthBudget` 与 `watchTransactionBudgetHint` 断言三端（总览、分类明细、记账提示条）输出完全一致；同时通过 `ensureMaterialized` 验证远期虚拟项按需落库的幂等性与并发安全性。
  - **辅助纯领域接缝（针对算法边界与性能护栏）**：直接针对 `RecurrenceExpander`（以及若抽离后的 `BudgetPendingProjector`）进行纯内存单元测试，覆盖 `DAILY`/`WEEKLY` 快进计算正确性、`countLimit - completedCountOffset`、`materializeFrom`、`endDate`、跨夏令时与 `nowYm + 24` 前瞻截断边界。
- **代码库既有先例（Prior Art）**：
  - 预算虚拟 Overlay 集成测试已采用 `LedgerServiceHarness` 驱动 `BudgetService` 与 `RecurringService` 的模式（可直接在既有预算虚拟投影与按需落库测试套件上补充本次收口的 3 类新场景：超 24 月前瞻上限、高频远期快进准确性、归档分类 `M > archiveYm` 虚拟待入账截断）。

## Out of Scope

- 不改变 `ProjectRecurringEventsCommand` 的物理物化窗口长度（维持当月 + 未来 1 个自然月），不为远期规划扩大 SQLite 物理写入范围。
- 不将周期账本整体重构为“纯虚拟 RRULE + Exception 表”模型，继续保留 `scheduled_transactions_view` 的 UUID 身份与二元作用域编辑机制（ADR-0005）。
- 不在月度报表（Reports）或交易搜索（Search）中引入虚拟待入账期次；账本列表的 24 个月内虚拟期次是本次明确纳入的范围，但仅用于展示与按需落库，不参与任何合计。
- 不在历史月（Review 模式）中把未入账或虚拟期次计入实际支出或达标判定。
- 不引入任何跨币种汇率换算或预算余额跨月结转。
- 不将 `BudgetDao` 内的内存 Overlay 逻辑在本次任务中搬迁抽离为独立的 `BudgetPendingProjector`（留作后续可选重构）。
- 不为 6 个月趋势图中的非目标月份展开虚拟待入账。
- 归档分类不联动停用其关联的周期规则（仅在 `M > archiveYm` 的预算待入账统计中排除）。

## Further Notes

- 不涉及任何数据库表结构变更或版本迁移。
- **当前落地进度**：本规格所描述的混合投影主体能力（`RecurrenceExpander`、自然月三阶段物化、`BudgetDao` 读时虚拟 Overlay、`WatchMonthBudgetQuery` / `WatchTransactionBudgetHintQuery` 历史月隔离与三端同口径、以及 `EnsureOccurrenceMaterializedCommand` 按需落库）已在 `feat/budget-aligned-recurring` 分支落地；24 个月前瞻上限、高频快进护栏、归档分类 `M > archiveYm` 物理与虚拟待入账统一截断也已完成。账本页月度待入账现已通过 `RecurringDao.watchMonthPendingBills` + `WatchMonthlyPendingBillsQuery` 接入同一套读时虚拟补齐与按需落库，`pendingBillMonths` 保持仅物理。
- **术语对齐**：全文严格遵循项目统一语言（`CONTEXT.md`），区分 *Pending bill exposure*（待入账敞口）、*Committed spend*（固定/已承诺支出）、*Discretionary spend*（自由支出）、*Budget timeline*（预算时间轴）、*Recurring series*（周期系列）与 *Source bill*（来源账单）。
