## 待人工审查项

1. **24 / 25 个月前瞻边界（Plan）**
   - 打开预算 → 切到 `now + 24` 月：周期支出应仍有虚拟待入账与固定支出基线。
   - 切到 `now + 25` 月：虚拟待入账应静默消失，只保留已物化的物理账单；页面不应出现免责提示或卡顿。
   - 24 个月按“当前月 + 24”计算，跨年（12 月）边界需各看一次。

2. **多年前起点的高频规则**
   - 建一条 `DAILY` 或 `WEEKLY`、起点在数年前的规则，选择“仅从今天起生成”。
   - 当月 Track 不应把今天之前的期次补进待入账；`now + 24` 月的日期相位应仍与原始起点对齐（例如起点是周一，远期展开也落在周一）。
   - 页面滚动、切月应及时响应，不应出现数秒白屏。

3. **归档分类的 M / M+1 截断**
   - 在预算里给分类设预算并保留活跃周期账单，归档该分类。
   - 归档当月 M：预算总览、分类行、记账表单提示条都应保留该分类的物理 + 虚拟待入账。
   - M+1：三端同时为 0，且分类不再出现在预算列表；账户/周期规则本身不应被停用或删除。
   - 归档后不重启应用，确认三端是实时刷新而不是等待重新进入页面。

4. **远期虚拟账单的按需落库与实时刷新**
   - 在 `now + 6` 月的分类详情点击一条虚拟待入账，确认生成标准 UUID 待入账并打开既有操作面板。
   - 连续快速点击同一条，确认只有一条物理行。
   - 对该期执行跳过或提前入账后，预算总览的待入账应立即下降（本次修复了 drift 触发器同 SQL 文本导致的流不刷新）。

5. **历史月 Review 与表单提示**
   - 切到上月 Review：实际支出与达标判断不含任何未入账/虚拟期次。
   - 把记账表单日期选到过去月份时，提示条显示的预计剩余应与预算页该月一致（当前 `BudgetHintUiMapper` 会把 Review 的 pending 置 0）。
   - 已知后续项：`watchCategoryBudgetHint` 原始实体仍返回过去月的物理 pending，若未来出现新的消费者需要在 DAO 层统一为零。

6. **账本页的 24 个月虚拟待入账（补充接入）**

   - 切到历史月或 `now + 25`：只剩物理行，不应凭空多出虚拟期次。
   - 点击一条远期虚拟账单：应先幂等落库，再弹出既有待入账操作面板；连续快速点击不应产生重复行。

   - 待入账行仍为灰色（与已跳过同色、无删除线）；失败行保持正常颜色。

## 代码审查遗留（非阻塞，P2）

- 归档分类的集成测试直接写 `categoriesView`，因为 `envelopeFor` 的 `recordedAt` 固定用 `DateTime.now()`，`FixedClock` 无法钉住归档月份；若未来把投影改为使用 `occurredAt`，需要补一条经过 `CategoryService` → 投影 → DAO 的回归测试。
- `archived == true && archivedAt == null` 时 DAO 计入待入账、预算计算器却视为无预算；正常投影不会产生该状态，属于 legacy 防御差异。
- 三个预算流的触发器现在依赖不同的 `SELECT 1 -- ...` 文本；新增触发器时必须保持文本唯一，现有测试覆盖了三种订阅顺序。
